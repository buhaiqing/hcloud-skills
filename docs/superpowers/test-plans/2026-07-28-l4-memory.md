## 1. Test taxonomy

### 1.1 `OutcomeMemory` (Plan A, Tasks 1–4)

Tests live in `hwcloud-skillcheck/internal/l4/outcome_memory_test.go`. Use
`t.TempDir()` for every test that touches disk.

#### 1.1.1 Record / append
- `TestOutcomeRecord_RoundTrip` — `json.Marshal` then `Unmarshal` returns the
  same value. All 14 spec fields round-trip with their JSON tags exactly per
  spec §5.
- `TestOutcomeMemory_RecordAppendsJSONL` — record 2 lines, read raw file, assert
  exactly 2 `\n`-terminated lines and that the bytes for each ID appear in
  order. **Replace the plan's `bytes.Contains` check with `json.Unmarshal` of
  each line into a fresh `OutcomeRecord` and a `reflect.DeepEqual` against the
  input** — `bytes.Contains` is too lenient (passes on partial overlap).
- `TestOutcomeMemory_Record_CreatesDirWith0700` — calling `NewOutcomeMemory`
  on a fresh path creates `.l4-memory/` with mode `0o700`. Use
  `info.Mode().Perm()` to check.
- `TestOutcomeMemory_Record_FileModeIs0600` — after the first `Record`,
  `outcomes.jsonl` mode is `0o600`. Mirror `TestOutcomeMemory_DirAndFileMode`
  in the plan but split into two tests so a failure points at the right thing.
- `TestOutcomeMemory_Record_AppendDoesNotTruncate` — pre-seed the file with a
  sentinel line, call `Record`, assert sentinel still present (defends against
  a future refactor that switches to `O_TRUNC`).

#### 1.1.2 Recent outcomes
- `TestOutcomeMemory_RecentOutcomes_OrdersByTimestampDesc` — seed 4 records
  with `ts = 00, 01, 02, 03` (mixed `(skill, action)`), assert
  `RecentOutcomes("huaweicloud-ecs-ops", "list", 10)` returns IDs in
  `[3, 1]` (most recent first, filtered to `ecs-ops/list`).
- `TestOutcomeMemory_RecentOutcomes_LimitTrimsResults` — seed 5 matching
  records, call with `n=2`, assert len == 2 and they are the two newest.
- `TestOutcomeMemory_RecentOutcomes_NZeroOrNegativeReturnsAll` — n=0 and n=-1
  both return every matching record (spec FR-2).
- `TestOutcomeMemory_RecentOutcomes_SkipsMalformedLines` — append a non-JSON
  line `"{ this is not json"` followed by valid lines; the malformed line is
  silently dropped (spec says "skip malformed"); valid lines still returned.
  Use `os.WriteFile` to write the bad line directly so the test is independent
  of `Record`'s encoding.

#### 1.1.3 Match (3-field, lookback)
- `TestOutcomeMemory_MatchOutcomes_3FieldFilter` — 4 records with the same
  `context_hash` set differently; the 3 that match `(skill, action, hash)` come
  back, the 4th (different hash) does not.
- `TestOutcomeMemory_MatchOutcomes_Lookback_24h` — seed one record with
  `ts = time.Now().Add(-48h)`, one with `ts = NowISO()`; query with
  `lookback = 24h`, assert only the fresh one is returned.
- `TestOutcomeMemory_MatchOutcomes_LookbackZeroReturnsAll` — lookback = 0
  returns every record matching the 3 fields regardless of timestamp (spec).
- `TestOutcomeMemory_MatchOutcomes_ExactlyAtLookbackBoundary` — record with
  `ts = now - 24h + 1s`; lookback = 24h; assert it IS returned (boundary is
  "strictly before cutoff" — see plan §Task 4). Document the off-by-one
  decision in a comment so the next maintainer doesn't flip it.
- `TestOutcomeMemory_MatchOutcomes_MalformedTimestampSkipped` — record with
  `Timestamp = "not-a-date"`. `MatchOutcomes` skips it; other valid records
  still come back. Confirms the `time.Parse` failure path is silent, not loud.

#### 1.1.4 Prune
- `TestOutcomeMemory_PruneOlderThan_KeepsRecent` — plan's test, but tighten:
  assert not just length but **ID set** of kept records.
- `TestOutcomeMemory_PruneOlderThan_DropsMalformed` — a line that fails
  `time.Parse` is dropped (counted in `dropped`).
- `TestOutcomeMemory_PruneOlderThan_EmptyFileNoOp` — file absent or empty;
  prune returns `(0, nil)`, file is left untouched (no tmp file left behind —
  see `TestOutcomeMemory_PruneOlderThan_NoTempLeftBehind`).
- `TestOutcomeMemory_PruneOlderThan_NoTempLeftBehind` — assert
  `os.ReadDir(filepath.Dir(path))` contains no `outcomes-*.jsonl.tmp` after a
  prune (cleanup-on-error path).
- `TestOutcomeMemory_PruneOlderThan_FreshFileHasMode0600` — after rename, the
  new file's perm is `0o600` (defends against the chmod-after-rename bug
  noted in review).
- **`TestOutcomeMemory_PruneOlderThan_ConcurrentRecordNoDrops` (C4 fix)** —
  spawn N=50 goroutines: 25 call `Record` in a loop, 25 call
  `PruneOlderThan(now-1h)` in a loop, all racing on the same `*OutcomeMemory`.
  After the dust settles, every record ever written must still be present
  **iff** its timestamp is at or after the cutoff. Implementation must hold
  the mutex across the read→write→rename sequence; this test makes the
  requirement falsifiable. **Do not** race this against the in-memory cache
  recommended in Eng-M4 (out of scope for this iteration).
- `TestOutcomeMemory_AutoPruneOnNewDropsOldRecords` — create a temp dir,
  pre-seed `outcomes.jsonl` with one record ts=2020-01-01 and one ts=now, then
  call `NewOutcomeMemory`. Assert only the recent record survives. This
  locks in the "auto-prune on init" contract from plan §Task 4.

### 1.2 `ContextMemory` (Plan B, Tasks 1–4)

Tests in `hwcloud-skillcheck/internal/l4/context_memory_test.go`.

#### 1.2.1 Save (atomic, perms)
- `TestContextMemory_Save_CreatesDirWith0700` — first save creates the
  `.l4-memory/` dir at `0o700` (idempotent with `NewOutcomeMemory`).
- `TestContextMemory_Save_FileModeIs0600` — after save, `context.json` is
  `0o600`.
- `TestContextMemory_Save_AtomicNoTempLeftBehind` — assert no `context-*.json.tmp`
  files after a successful save.
- `TestContextMemory_Save_OverwriteOnSecondCall` — save a Context, then save a
  different one; `Load` returns the second one (the rename replaced the file).
- `TestContextMemory_Save_NilContextRejected` — `Save(nil)` returns an error,
  no file written.
- `TestContextMemory_Save_WrongSchemaRejected` — `Save(c)` with
  `c.Schema != ContextSchema` returns an error and does not touch disk.
- `TestContextMemory_Save_AtomicMidCrashSimulation` — simulate a crash
  mid-write by writing a partial tmp file (e.g. `os.WriteFile` a truncated
  payload to `context-xxx.json.tmp`), then call `Load`. `Load` must succeed
  and return the **previous** content (or a fresh context on first run), not
  the partial tmp. This is the spec NFR-5 crash-safety requirement.

#### 1.2.2 Load (first-run, schema-reject, session-rotate)
- `TestContextMemory_Load_FirstRunReturnsFreshContext` — no file exists; `Load`
  returns a `*Context` with `Schema = "context-memory/v1"`, non-empty
  `SessionID` matching the v4 regex `^[0-9a-f-]{36}$` (or the fallback prefix
  `fallback-` if the test runs on a hostile env; gate with a check), and
  populated `CreatedAt`/`LastUpdated`.
- `TestContextMemory_Load_FirstRunNoSideEffect` — call `Load` twice; the two
  `SessionID`s differ (no persistence on first-run path). This catches a
  regression where someone adds a `Save` to `freshContext`.
- `TestContextMemory_Load_RejectsUnknownSchema` — save a Context with
  `Schema = "context-memory/v999"`; `Load` returns an error mentioning
  schema. Assert the existing file is **not** rewritten or repaired (so a
  bad on-disk state stays bad until an operator acts).
- `TestContextMemory_Load_RotatesExpiredSession` — save a Context with
  `CreatedAt = now - 48h`. `Load` returns a context with a new `SessionID`
  (not equal to the saved one) and a refreshed `CreatedAt` (today's date per
  `time.Now().UTC().Format("2006-01-02")`). `RecentTasks` is preserved
  through rotation. **Note brittleness** — see Section 5.
- `TestContextMemory_Load_PreservesFreshSession` — save a Context with
  `CreatedAt = now - 1h`. `Load` returns the same `SessionID` and the same
  `CreatedAt` (no rotation under 24h).
- `TestContextMemory_Load_MalformedJSONRejected` — write garbage to
  `context.json`; `Load` returns an error. Confirms the `Unmarshal` failure
  path returns `parse:`-prefixed error (caller can distinguish from
  schema-reject).

#### 1.2.3 Mutation API (cap-pruning, delete-via-empty-string)
- `TestContextMemory_RecordTask_PrependsAndCapsAt20` — record 25 tasks; assert
  len == 20, newest-first by `TaskID`, oldest kept is `t-05` (cap = 20, drop
  oldest 5).
- `TestContextMemory_RecordTask_RunningAddsToOpen` — status=`running` adds to
  `OpenTasks`; status=`completed` does not.
- `TestContextMemory_RecordTask_PausedAddsToOpen` — status=`paused` adds to
  `OpenTasks` (spec mutation API §5).
- `TestContextMemory_RecordTask_OpenTasksCappedAt50` — record 60 running
  tasks; `OpenTasks` len == 50, oldest dropped.
- `TestContextMemory_CloseTask_RemovesFromOpen` — `CloseTask("r-1")` removes
  the ID; `OpenTasks` retains the rest. Calling on a non-existent ID is a
  no-op (no error).
- `TestContextMemory_RecordError_PrependsAndCapsAt20` — 25 errors → 20 kept,
  newest first.
- `TestContextMemory_SetPreference_AddAndRead` — set a key, read it back.
- `TestContextMemory_SetPreference_EmptyStringDeletes` — set
  `("default_region", "cn-north-4")`, then `("", "")` deletes. Assert key
  not in map. Plan's existing test; keep but also add the "set twice, then
  delete twice is idempotent" case.
- `TestContextMemory_SetPreference_NilMapInitialized` — load a Context with
  nil `Preferences` map (write the JSON `"preferences": null`); set a key;
  assert no panic, key is now present.
- `TestContextMemory_LastUpdatedAdvancesOnMutation` — save a Context at
  `LastUpdated = "2026-07-28T08:00:00Z"`, sleep 1s, mutate, load, assert
  `LastUpdated` is later (uses `NowISO` not the test's input). Tolerate
  ≤1s clock skew with a comment.

### 1.3 `Self-healing` (Plan A, Tasks 5–7)

Tests in `hwcloud-skillcheck/internal/l4/self_healing_test.go`.

#### 1.3.1 `isTransient` (table-driven)
The plan's test covers the main patterns. Add:
- Case-insensitive: `"CONNECTION RESET BY PEER"` → true; `"Service Unavailable"`
  → true (uppercase).
- Substring: `"got a connection reset by peer mid-request"` → true (not
  whole-word match).
- Punctuation: `"401 Unauthorized."` → true; `"5xx 503 error"` → true.
- Negative: `"Connection refused"` (TCP-level, not "reset") → false; document
  this is intentional (not a transient pattern; user controls retry via
  MaxRetries).
- Empty string: `""` → false.

#### 1.3.2 `HealingPolicy.IsZero` / `defaultHealingPolicy`
- `TestHealingPolicy_IsZero_AllZero` — `HealingPolicy{}.IsZero() == true`.
- `TestHealingPolicy_IsZero_AnyFieldNonZero` — table-driven, one field set
  per case: `{MaxRetries: 1}`, `{LookbackWindow: time.Second}`, etc. Each
  returns false. Especially the sum-check trap (M1) — set only
  `MaxRetries = -1` and assert `IsZero() == false` (the sum-check bug would
  misclassify this as zero; `IsZero()` is field-wise, not sum-based).
- `TestDefaultHealingPolicy_PopulatesDestructiveVerbsFromRbac` — assert
  `defaultHealingPolicy().DestructiveVerbs` equals the output of
  `ExtractHighRiskVerbs()` (Eng-M3 fix). Catches drift if RBAC adds a verb.
- `TestDefaultHealingPolicy_MinSamplesFive` — `MinSamples == 5`,
  `LookbackWindow == time.Hour`. Lock in the spec defaults.
- `TestDefaultHealingPolicy_MaxRetriesZero` — `MaxRetries == 0` (no auto-retry
  by default; spec FR-3 safe-default).

#### 1.3.3 `PreExecHook` decision tree
Each branch becomes a named test (one behaviour per test, per CLAUDE rules).

- `TestPreExecHook_EmptyMemoryReturnsProceed` — `t.TempDir()` + `NewOutcomeMemory`,
  no records, any policy with `FailureRateSkipThreshold > 0` and
  `MinSamples > 0` → `proceed`.
- `TestPreExecHook_BelowMinSamplesProceeds` — 2 records, MinSamples=5, all
  failures → `proceed` (the plan's test; tighten by also asserting the
  returned `Reason == ""`).
- `TestPreExecHook_AtOrAboveThresholdSkips` — exactly MinSamples records, all
  failures, threshold=0.5 → `skip` with `Reason` mentioning failure.
- `TestPreExecHook_BelowThresholdProceeds` — MinSamples records, 3 failures +
  7 successes, threshold=0.5 → `proceed` (rate = 0.3).
- `TestPreExecHook_ExactlyAtThresholdProceeds` — 5 records, 3 failures,
  threshold=0.6 → `proceed` (3/5 = 0.6 ≥ 0.6 means the spec says `>=`; assert
  the boundary is **inclusive on the threshold**. Document the comparator
  choice in a comment).
- `TestPreExecHook_ZeroThresholdProceeds` — `FailureRateSkipThreshold = 0` →
  `proceed` regardless of history (spec safe default).
- `TestPreExecHook_ZeroMinSamplesProceeds` — `MinSamples = 0` → `proceed`.
- `TestPreExecHook_LookbackExpiredProceeds` — MinSamples records, all
  failures, threshold=0.5, but the most recent record's timestamp is older
  than `LookbackWindow` → `proceed`. Catches M5: a stale 6-month-old failure
  spike must not block a step today.
- `TestPreExecHook_LookbackExactlyAtBoundary` — newest record exactly
  `LookbackWindow` ago. Implementation reads
  `time.Since(last) > p.LookbackWindow` (strict), so equal = within window =
  `skip` if failure rate holds. Document the off-by-one.
- `TestPreExecHook_OnlyMatchingRecordsCounted` — 5 records for
  `(skillA, actionX)` failures, plus 5 records for `(skillB, actionY)`
  successes. Query step `(skillA, actionX)` with MinSamples=5, threshold=0.5
  → `skip`. The 10 `skillB` records must not influence the decision.
- `TestPreExecHook_ActionMismatch` — records for `action=list`, query
  `action=delete` → `proceed`. (Filter is exact equality on both fields.)

#### 1.3.4 `PostFailureHook` decision tree
- `TestPostFailureHook_ZeroMaxRetriesEscalates` — already in plan. Assert
  `Reason` contains "max retries" or empty (be lenient on reason phrasing
  since the spec says "max retries reached" but the plan says
  `"max retries reached"`).
- `TestPostFailureHook_AtMaxRetriesEscalates` — `MaxRetries=2`,
  `retryCount=2` → `escalate`.
- `TestPostFailureHook_BelowMaxRetriesTransientRetries` — `MaxRetries=3`,
  `retryCount=0`, `Error="connection reset by peer"` → `retry`,
  `Reason` contains "transient".
- `TestPostFailureHook_BelowMaxRetriesPermanentEscalates` —
  `Error="permission denied"` → `escalate`, `Reason` contains "non-transient"
  or the original error.
- `TestPostFailureHook_DestructiveVerbEscalates` — `step.Verb = "delete"`,
  any error, retry budget available → `escalate` BEFORE transient check
  (decision tree order). This is the test for M3 fix.
- `TestPostFailureHook_VerbMatchIsExactEqualFold` — `step.Verb = "undelete"`,
  `DestructiveVerbs = ["delete"]` → `escalate` is the goal, BUT with the
  `EqualFold(step.Verb, "delete")` check this is `false` so it falls through.
  This is the M3 contract. **The action name `undelete-restore` must not
  classify the step as destructive.** Plan's test `TestPostFailureHook_DestructiveEscalates`
  uses `step.Action = "delete-instance"`; that's the wrong test because
  the implementation reads `step.Verb`, not `step.Action`. Tighten to
  `step.Verb = "delete"`.
- `TestPostFailureHook_ActionDoesNotDriveDestructiveness` — `step.Action =
  "delete-something"`, `step.Verb = "list"` → `retry` (transient), proving
  the verb is the gate, not the action name.
- `TestPostFailureHook_RetryBudgetDecisionOrder` — table-driven, all 4
  branches in priority order. Document the decision tree as a comment in
  the test file so the order is greppable.
- `TestPostFailureHook_ReasonContainsErrorForDiagnostics` — the
  `Reason` field must include the original `result.Error` (truncated or
  not — implementation choice) so triage is possible from logs alone.

## 2. Property-based / fuzz tests

Two invariants are worth fuzzing. Use `testing.F` (Go 1.18+ stdlib).

### 2.1 `OutcomeMemory`: `Record → PruneOlderThan` invariant
```
For any sequence of N Records, where each Record has a timestamp in
[cutoff - D, cutoff + D] (D = 1 year), and any single PruneOlderThan(cutoff)
invocation interleaved at any point in the sequence:

  Let K = the set of records whose timestamp is at or after cutoff.
  After every observation point, RecentOutcomes / MatchOutcomes must
  return a superset of K minus any record not yet visible due to
  append-buffer flushes.

Concretely: after N Record calls (no prunes), ReadAll returns N records.
After Record → PruneOlderThan(cutoff) in any order, the surviving
records' IDs are exactly those with timestamp >= cutoff, regardless of
interleaving (assuming proper mutex holding; the C4 race fix is
required for this to pass).
```

`testing.F` driver: a seed corpus of mixed-timestamp records, plus a
goroutine that runs `PruneOlderThan` in a loop. After `t.Cleanup`, count
records that are missing vs records that should have survived. The test
fails on the original C4 race; passes after the mutex-held-across-rename
fix.

### 2.2 `ContextMemory`: mutation cap invariant
```
For any sequence of mutation calls (RecordTask, RecordError, CloseTask,
SetPreference) on a fresh ContextMemory, the resulting Context always
satisfies:
  len(c.RecentTasks)  <= MaxRecentTasks
  len(c.RecentErrors) <= MaxRecentErrors
  len(c.OpenTasks)    <= MaxOpenTasks
  c.Schema            == ContextSchema
  c.SessionID         != "" after first Load
  After any SetPreference(k, "") call, k not in c.Preferences.
```

`testing.F` driver: random sequence of mutations (max 100 ops), then Load,
then assert all invariants. Catches cap-pruning bugs in any combination
of mutation order.

## 3. Integration scenarios (both plans together)

### 3.1 First run (empty memory)

  `FailureRateSkipThreshold=0.5, MinSamples=5, LookbackWindow=1h`. Assert

  `GCLDecision == "SKIPPED_BY_HEALING"`. Assert `ContextMemory` shows the
  skip in `RecentErrors` (with `ErrorClass="skipped"` or whatever the
  implementation chooses) — confirms both memories recorded the event.

### 3.3 Cross-call memory reflects task lifecycle
- `TestIntegration_CrossCallMemory_LifecycleRecorded` — Run 1:
  `HandleFault` for a single-step task that succeeds. Run 2: `Load`
  the `ContextMemory` and assert:
  - `RecentTasks[0].TaskID` matches Run 1's task ID.
  - `RecentTasks[0].Status == "completed"`.
  - `RecentTasks[0].PrimarySkill == "huaweicloud-ecs-ops"` (or whatever
    skill was used).
  - `OpenTasks` is empty (Run 1's task was closed on completion).
- `TestIntegration_CrossCallMemory_FailedStepRecordsError` — same as
  above but the step fails. Assert `RecentErrors[0]` has the failure
  captured with `ErrorClass="permanent"` (or "transient" depending on
  the error message).
- `TestIntegration_CrossCallMemory_SessionRotatedAfter24h` — Save a
  Context with `CreatedAt = now - 25h`, run `HandleFault`, then `Load`
  again. Assert `SessionID` changed and the original task is still in
  `RecentTasks` (rotation preserves history).

### 3.4 Trust computation under both memories
This is the spec FR-2 / ADR-0009 use case (the prompt mentions
"ADR-0009 trust computation uses both outcome + context correctly").
- `TestIntegration_TrustComputation_UsesBothMemories` — build a
  `TrustComputer` (or whatever the existing symbol is; if absent, this
  test is a placeholder for ADR-0009) that takes both `*OutcomeMemory`
  and `*ContextMemory`. Inject:
  - Outcome memory: 3 successes for `(skill, action)`.
  - Context memory: 1 `RecentError` for the same `(skill, action)` with
    `ErrorClass="permanent"`.
  - Recent task with status `failed`.
  Assert the resulting trust score is **lower** than the
  outcome-only baseline (proven by running the same inputs with
  `ContextMemory = nil` and comparing).

  **If `TrustComputer` does not exist yet** (it's deferred per the
  prompt), this test is a stub: `t.Skip("ADR-0009 trust consumer not
  yet implemented")`. Keep the test file so the contract is locked in

| Module | Target | Testability concerns |
|--------|--------|----------------------|
| `outcome_memory.go` | 100% lines + 100% branches | The 4 public methods (Record, Recent, Match, Prune) are all in the spec; cover them. The internal `readAll` is exercised by Recent/Match/Prune. |

**Seam injection flags** (these are recommendations, not directives — the
implementer can accept the brittleness if the cost is high):

1. **`time.Now()` injection** — `PreExecHook` uses `time.Since(last)` and
   `time.Now().Add(-lookback)`. For NFR-6 determinism, both functions
   should accept an optional `now time.Time` parameter (or a package-level
   `var nowFunc = time.Now` test seam). The plan does not call this out,
   but every "lookback expired" test will be flaky without it. **Flag
   for the implementer: either inject `now` or accept wall-clock
   dependency in those branches and add a `@note flakiness` in the test.**
2. **`crypto/rand` injection** — `newOutcomeID()` and `newSessionID()`
   read from `crypto/rand`. For test stability, this is fine (the values
   are not asserted in any test other than `Load_FirstRunReturnsFreshContext`,
   which only checks the v4 regex shape). **No seam needed unless an
   exact-ID test is added; if so, accept the var injection.**
3. **`os.OpenFile` / `os.CreateTemp`** — both can stay real; tests use
   `t.TempDir()` for isolation. No mocking needed.
4. **`NowISO()`** — already a function. Tests assert format, not exact
   value. No seam needed.
5. **`hashContext`** — the plan does not yet define this (Task 8
   introduces it). **Flag for the implementer:** add a unit test that
   asserts two calls with the same `(skill, action, stable_args)` return
   the same hash, and two calls with different `volatile_args` (e.g.
   `--query-window=now`) return the same hash. Eng-m1: volatile fields
   must be stripped before hashing.

## 6. Brittleness warnings (be specific)

| # | Brittle pattern | What fails | How to avoid |
|---|----------------|-----------|--------------|
| **B1** | `TestContextMemory_Load_RotatesExpiredSession` asserts `loaded.CreatedAt` starts with `time.Now().UTC().Format("2006-01-02")`. | Test runs at 23:59:59 UTC; the assertion captures today's date; assertion at 00:00:01 UTC compares against a different day. | Compute the expected date once at the top of the test (`expected := time.Now().UTC().Format("2006-01-02")`) and assert against that, not a re-formatted `time.Now()`. |
| **B2** | `TestContextMemory_Load_FirstRunReturnsFreshContext` calls `Load` twice and expects different `SessionID`s. | If the implementation regresses to "first run saves to disk", the test fails. | This is the correct behaviour to lock in. Tolerate with `@note intentional: this test fails if first-run accidentally persists`. |
| **B3** | Tests that use `bytes.Contains(raw, []byte(`"id":"a"`))` (Plan A's `TestOutcomeMemory_RecordAppendsJSONL`). | Passes on partial overlap (e.g. a future record with `"id":"ab"` would satisfy the `id":"a"` check). | Replace with `json.Unmarshal` + `reflect.DeepEqual` on the parsed struct. Brittleness: very high. |
| **B4** | `TestOutcomeMemory_MatchOutcomes_Lookback_24h` seeds with `time.Now().Add(-48h)` and `NowISO()`. | Runs at the boundary of 24h computation: floating-point duration math? No, `time.Duration` is integer ns — no float issue. But the test does depend on the fresh record being "now", which is fine. | Leave as-is. **However**: when running on a slow CI machine, the seeded record is timestamped at test start, and `MatchOutcomes` uses `time.Now().Add(-lookback)` at read time. If `lookback=24h` and the test takes >0s, no drift — fine. |
| **B5** | Tests that compare `info.Mode().Perm()` to a literal `0o700`. | CI under Docker may apply umasks that downgrade effective mode. | Use `info.Mode().Perm() & 0o700 == 0o700` (mask check) or document the umask requirement. The persistence.go test (`TestPersistTask_DirMode_0700`) already exists; match its pattern. |
| **B6** | `TestContextMemory_LastUpdatedAdvancesOnMutation` uses `time.Sleep(1s)`. | Slows the test suite. | Use a tolerance of `time.Now().Add(-1*time.Second).Before(parsed)` instead of `time.Sleep`. |
| **B7** | Map iteration order in `TestContextMemory_Load_FirstRunReturnsFreshContext` if any future code iterates `Preferences`. | Test depends on `Preferences["default_region"]` being set in a specific order. | Don't iterate maps in production code that affects the test path. If a test needs to assert the whole map, compare with `reflect.DeepEqual` (order-independent via `map[string]string`). |
| **B8** | `TestRunExecutionLoopWithHealing_DestructiveOpNeverRetries` asserts `StubExecutor.counter == 1`. | If a future change adds a pre-flight executor call, the test fails. | Add a comment naming the executor seam: `// StubExecutor called exactly once — the destructive-verb gate fires before any retry. If this breaks, the gate moved; consult plan §Task 8.` |
| **B9** | Tests that use `t.TempDir()` and the OS's `os.MkdirAll(0o700)`. | On systems with a strict umask, the actual mode may be `0o755`. | Spec says mode is set explicitly via `MkdirAll(0o700)`. On Linux this works as long as the process umask doesn't AND-out the bits. Document the umask assumption in the test. |
| **B10** | `TestPostFailureHook_ExactlyAtThresholdProceeds` / `_AtOrAboveThresholdSkips` boundary tests. | Implementation changes the comparator from `>=` to `>` and the tests break. | Document the comparator in a comment; add `@note spec FR-4 says >= threshold`. |
| **B11** | The plan uses `string(rune('a' + i))` to generate IDs. | For i > 25, the rune wraps (`'a' + 26 = '['`), producing non-letter IDs that the test still accepts because they're compared by string equality, not format. | Use `fmt.Sprintf("a%d", i)` instead. The plan's pattern works for small N but is fragile for the concurrency test (N=50). |
| **B12** | `TestIntegration_AfterSixFailures_NextRunSkips` depends on the second `HandleFault` call seeing the outcomes from the first. | If a future change makes `HandleFault` use a separate temp dir per call, the test fails. | Document in the test: `// Both runs use the same root (t.TempDir() is process-global per test).` and assert `root` is the same in both. |
| **B13** | Plan A's `TestRunExecutionLoop_PreExecSkipsBadHistory` uses `ID: "old" + string(rune('a'+i))`. Same wrap-around as B11. | Same fix: `fmt.Sprintf("old-%d", i)`. |
| **B14** | `TestHealingPolicy_IsZero_AnyFieldNonZero` — setting `MaxRetries = -1` is unusual; if a future invariant is "non-negative", the test breaks. | Add a comment: `// Negative MaxRetries is intentionally a non-zero value; the IsZero contract is per-field, not per-semantic-validity.` |
